# Named watchlists

## Account and stock-page behavior

New accounts start with no watchlists. Users can create any number of named lists, add descriptions, pin lists, search them, and open them from the sidebar. Lists can be empty. Their expandable summaries show instrument, monitored-instrument, and unread-notification counts; member tables load 50 rows at a time.

On a stock page, enabling stars stays a draft until **Apply changes**. If that draft enables monitoring, a dialog asks which watchlists should receive the new follows, with inline creation for the first list. Existing memberships are preselected and editable: a ticker already followed for congressional or insider alerts can gain technical follows in the same list. Unchecking a list skips the additions without removing its membership or existing follows. Cancel preserves the draft and sends no mutation. Memberships and alert changes commit in one transaction. Removing membership is a separate action in Watchlists. Disabling rules alone does not require choosing a list. The membership-only action uses **Add to watchlists** wording.

Each list stores its own monitoring defaults and each member's requested follows. The existing account/instrument subscriptions are the union of those requests: adding AAPL to another list does not create another copy of the same rule, scheduled check, or notification. Existing scheduling also deduplicates by instrument and interval across accounts. Removing a membership stops only follows that no remaining list requests. Event history and existing signal lifecycle records remain accessible. List coverage and monitored counts show the follows requested by that list; unread counts are scoped to the list's recorded notification origins, with matching follows used for older history without origins.

New members inherit the selected list's defaults, including additions from the stock page's **In watchlists** action. Automated Technical Outlook interval stars share the pattern draft: **Apply changes** saves both together, with one watchlist prompt when enabling follows. **Follow all / Unfollow all** also changes the draft until applied. Cancel or a failed save preserves every pending selection. Congressional and insider follows still use their own immediate actions and watchlist picker. Stock-page unfollows and the **Followed outlooks** page's account-wide unfollow remove the matching request from every list; later unrelated edits cannot silently restore it.

Opening a list from Home, Watchlists or the sidebar shows its dedicated overview, including each ticker's unread count and signal types paired with their intervals. Ticker links open `/signals?watchlistId=?&ticker=?` with an exact ticker match. **View all signals** opens a combined archive of technical signals, congressional activity and insider activity scoped to the list. All three share database sorting and pagination. Activity filings appear in All, Unread and Completed; Active is reserved for technical setups. Filings have no technical setup score or trade-plan outcome. Sorting, filters, pagination, signal-detail return links and deletion preserve the watchlist scope. The archive retains recorded history after follows change; other accounts cannot access the list. Congressional/insider detail links return to the same filtered watchlist archive. Automated outlook notifications retain their existing separate pages. Search and instrument-type controls align on desktop and stack on mobile.

## Monitoring and email settings

**Mark all as read** is available beside the dashboard's All ticker alerts link, in an opened watchlist, and in the watchlist and account signal archives. The dashboard action covers congressional and insider activity only. Watchlist actions cover every matching technical, outlook, congressional and insider notification; the general All signals action covers all four kinds across the account. These actions span every page and ignore the archive's current ticker/state filters. Read state is shared across overlapping lists. The page refreshes after success to update counts and highlighting; failed requests retain the page and allow retry. The CSRF-protected POST endpoint checks ownership, skips deleted/already-read notifications, preserves history and follows, and updates all included kinds in one transaction.

Creation and editing share a **Signals to follow** section. Candlestick, Elliott Wave and Harmonic buy/sell signals have separate Daily, Weekly and Monthly choices. Automated technical outlook has the same three intervals. Quick actions select all technical follows, all intervals for one type/direction, or all types for one interval. Congressional and corporate insider ticker alerts apply to stocks only; indexes and ETFs are skipped for those options.

**Allowed signal types** is independent of follows: all six types are allowed initially, including on existing lists. Disabling a type prevents new follows through stock actions, bulk selection and imports. The editor previews affected follow counts; saving removes only that type's requests from this list, synchronizes the account-wide union, and preserves memberships, other lists and saved history (including older notifications without origins). Re-enabling a type does not automatically follow it. Restrictions-only edits do not replace individual ticker preferences. The stock picker explains incompatible lists, and the server enforces the same permissions transactionally. Delayed import jobs use current restrictions.

One **Enable email notifications** switch controls email for the list. New lists start with email off. Followed signals always appear on the website. Changing email leaves the selected signal types, intervals and individual member follows intact. Email covers new signals and their lifecycle updates, still subject to account preferences and the server email switch. Email alone does not activate monitoring. If the same signal is requested by multiple lists, one matching list opting in is enough for a single email. Queued technical emails recheck current list preferences before delivery, so a later opt-out also suppresses pending mail.

Saving changed Watch selections queues application to every existing member and all newly selected instruments in that list. Other lists keep their requests. Email-only edits apply immediately and preserve individual member follows. A warning identifies lists whose members have individual overrides. Names, defaults and the background job are saved in one transaction; validation failure leaves them unchanged. Existing lists preserve their prior follows and email behavior until edited. Retried jobs use the list's latest defaults rather than replaying obsolete settings.

## Index imports

Creation and editing use a wide rectangular editor with instrument selection and follow settings side by side on desktop, stacking on smaller screens. The name and description sit together, and save/cancel controls stay visible while content scrolls.

The index browser uses clickable continents, then countries, then a checkbox for every available index in that country. Checking an index opens a choice dialog: **Index only**, **All stocks in the index**, or **Both**. Confirmation adds the choice to **Selected additions**; users can change its mode, remove it, or uncheck the index. Cancel or Escape leaves the draft unchanged. Switching countries or continents preserves existing selections. Individual ticker search remains available, and removing an index choice preserves independently selected tickers. Nothing is saved until the watchlist is reviewed and saved.

Selections can combine several indexes. A preview deduplicates overlapping listings and shows existing members, new monitoring, and capacity before import.

The bundled catalog has 24 snapshots covering the US, Canada, the UK, Germany, France, the Netherlands, Belgium, Spain, Switzerland, Italy, Portugal, Sweden, Finland, Denmark, Norway, Poland, the euro area, Japan, Hong Kong, India, Australia, and Brazil. It includes the S&P 500, Nasdaq-100, Dow Jones, TSX 60, Nikkei 225, and other major indexes. This is a supported catalog, not an exhaustive directory of every country or exchange; Africa is not included yet.

Source URLs and capture dates are stored in `src/main/resources/market/watchlist-indexes.json` and shown in the selector. `asOf` is the date the source snapshot was captured, not a guarantee of the index provider's effective constituent date. Sources include the linked Wikipedia constituent tables, Bankier for WIG20, and B3 for Ibovespa. Imported lists are snapshots and do not automatically rebalance. A later catalog update does not alter existing lists.

Foreign listings use exchange-qualified symbols, such as `RY.TO`, `ASML.AS`, and `7203.T`, keeping them distinct from US listings. Twelve Data requests translate those symbols into local symbols and market identifiers; the existing provider-alias registry still takes precedence.

Imports and bulk monitoring changes are durable database jobs processed in small batches. Per-item transactions, leases, unique memberships, and idempotent processing support interruption and retry. Users can close progress and reopen **Recent imports**. Successful items remain saved if another item fails. Failed members retain their previous settings until a successful retry; the editor indicates when individual member requests differ from list defaults.

Watchlist count and membership do not consume monitoring capacity. Existing monitoring limits remain configured through `ALERTS_MAX_TRACKED_STOCKS_PER_USER` (default 300) and `ALERTS_MAX_GLOBAL_TRACKED_STOCKS` (default 500). Congressional and insider follows retain their separate limits (default 50 each). A complete S&P 500 list can be saved without alerts at those defaults; enabling alerts for all its constituents requires larger configured capacity and sufficient provider resources. The preview explains unavailable alert services, capacity limits and skipped non-stock ticker alerts. Import completion means membership/rules were saved, not that market history or an analysis is already available.

## Migration and notification history

Flyway V62 creates list membership and migrates the distinct union of all four existing active follow types into one **My watchlist** per existing follower. Empty accounts receive no list. It retains existing rules and subscriptions. V63 creates import jobs. V64 adds list settings, backfills per-member requests from existing follows, and keeps account-wide unfollow requests synchronized. V65 attributes new notifications to the lists requesting that signal. V66 indexes signal origins for scoped archives and unread counts. V67 adds allowed-type restrictions, with every type allowed by default, and excludes disallowed types from new notification attribution. Normal application startup applies the migrations.

Database triggers capture list names and memberships when technical, outlook, congressional, or insider notification rows are created. Homepage notification rows show these names. Renaming a list does not rewrite historical attribution; deleting it leaves the saved name marked `(deleted)`. Older notifications without a snapshot show **Earlier notification**. Names shared by multiple lists are allowed; stable IDs distinguish those lists internally.

Membership and follow mutations enforce account ownership and CSRF protection. Account-row locks serialize concurrent membership changes. List deletion never deletes notification history. A user's unread event may count in several list summaries when those lists requested the same signal; the homepage notification itself appears once.

## Verification

Run Java integration tests against a dedicated PostgreSQL schema, never a production schema. For example, with the development database connection configured:

```powershell
.\mvnw.cmd -q '-Dtest=NamedWatchlistIntegrationTest,TechnicalWatchlistIntegrationTest,AlertControllerTest,MarketListingSymbolsTest,FrontendSecurityTest' '-Dspring.flyway.default-schema=watchlist_feature_test' '-Dspring.jpa.properties.hibernate.default_schema=watchlist_feature_test' '-Dspring.datasource.hikari.schema=watchlist_feature_test' '-Dwatchlists.imports.worker-enabled=false' '-Ddesign.preview.capture=true' test
npm ci
npm test
npm run test:watchlists:browser
```

The browser checks use the rendered test templates and production scripts/styles with deterministic API fixtures. They cover desktop/mobile layouts, geographic selection, technical and email choices, email-only edits and reloads, preview-before-save, background progress, first-list creation, multiple selection, and cancellation. Screenshots are written under `target/watchlist-browser`. Windows uses installed Edge by default; set `PW_BROWSER` to an installed Playwright browser channel on other environments. Node dependencies are development/test tools only.

The Java suite covers atomic saves and rollback, ownership/CSRF, all four notification origins, deduplication of scan jobs, overlapping list settings, email opt-ins and queued opt-outs, stock/ETF eligibility, removal, pagination/filtering, import retry, and migration of legacy accounts in a separate disposable schema. The JavaScript tests exercise the real settings controls and stock Apply-changes save function, including cancellation without mutations.
